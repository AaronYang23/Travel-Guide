# Proposal

## Why

通用旅游攻略很难体现个人偏好，使用者也可能连目的地都未确定。需要一个从“去哪玩”开始收集旅行条件、推荐可选目的地，并在用户确认后生成可继续修订的个人攻略的仓库内 Skill。

## What Changes

- 新增“去哪玩”流程：目的地未定时，询问出行时间、天数、出发地、人数、预算、交通方式、旅行类型、节奏及不喜欢的地点；可接受的单程时间在相关时纳入约束。
- 根据本次旅行画像分析并给出候选目的地 Top N，说明适配理由与取舍；用户选择或确认后，再生成“行程 / 吃 / 住 / 玩”的完整攻略。
- 已知目的地时可直接根据现有条件生成带假设的草案；后续通过反馈修订，不要求先填完所有偏好。
- 将用户明确要求长期保留的偏好记录在独立资料中，与本次旅行条件、暂时假设区分；不预置具体喜好。
- 对开放时间、价格、交通等时效信息标明核实状态；没有可用来源时不伪称已经查证。
- 初版仅输出对话中的攻略，不自动预订、发布或保存每次行程文件。

## Capabilities

### New Capabilities

- `personal-travel-guide`: 在目的地未定时逐步建立当次画像、推荐并确认候选地，在目的地确定后生成和修订注明假设及核实状态的攻略。

### Modified Capabilities

无。

## Impact

- 在项目的 `.agents/skills/` 下新增 Skill 入口和必要的偏好资料；不修改已有 OpenSpec Skill。
- 不引入运行时依赖或外部服务；实时资料查询取决于执行环境已有的工具和权限。
- 当前仓库只有简短 README 和 OpenSpec 配置，尚无攻略数据或既有产品接口；初版以对话式使用为边界。
