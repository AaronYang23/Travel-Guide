# Design

## Context

项目目前只有 README、OpenSpec 配置和 `.agents/skills/` 中的 OpenSpec 工作流，没有旅游攻略实现或现成数据。具体个人偏好尚未收集；设计必须允许空偏好档案启动，并随着后续对话完善。行为契约见 `specs/personal-travel-guide/spec.md`。

## Goals / Non-Goals

**Goals:**

- 让仓库内的 Skill 在目的地未定时先推荐可比较的候选地，待用户确认后再形成完整攻略。
- 已知目的地或部分喜好未定时仍可从已知条件推进，不把全部问题设为前置问卷。
- 使一次性旅行条件、草案假设和可复用的长期偏好有清晰边界。
- 保持入口简短，之后新增偏好无需反复改写流程指令。

**Non-Goals:**

- 构建应用、数据库、偏好推断模型或自动预订集成。
- 将“去哪玩”实现为独立的应用页面或接入外部 AI 推荐服务。
- 初版自动保存每一份攻略或生成固定格式的旅行文档。

## Decisions

### 1. 使用项目级 Skill 和独立偏好资料

在 `.agents/skills/personal-travel-guide/` 放置 `SKILL.md` 和 `references/preferences.md`。前者仅记录适用场景、交互流程、输出与核实边界，并在规划时按需读取后者；后者初始不含假定的个人喜好，只保存用户明确要求长期保留的偏好及其修改。相比把个人喜好写死在 `SKILL.md`，这个结构允许独立修订偏好而不影响工作流；相比数据库或脚本，它符合当前纯文档仓库的规模。

### 2. 用对话入口和当次画像驱动目的地发现

把“去哪玩”作为 Skill 的对话入口，而不是额外创建 UI。目的地未定时，按需收集九类信息：什么时候去、几天、从哪里出发、几个人、预算、交通方式、旅行类型、轻松或紧凑的节奏、回避的地点或体验；旅行类型提供人文、古镇、自然、城市、美食等示例，允许多选和“不确定”。用户曾提出的单程最长时间若已提供则作为约束，比较候选时确有需要再补问。已知答案不重复问，未知答案保留空缺，不自动转成长期偏好。相比一次性固定问卷，这种方式可在对话中逐步完成画像。

### 3. 当前会话内分析、候选确认后再出完整攻略

用当次画像和已保存偏好在当前会话内分析目的地，无独立推荐服务，也不把用户画像发送给另一个 AI。按旅行时段、出发地与交通可达性、预算、同行人数、体验类型、节奏和回避项筛选并排序；Top N 的数量随可信候选和用户要求调整，不为凑数加入不合条件的地点。每处简述匹配理由、已知交通耗时或待核实状态、预算取舍和不适配因素。若约束冲突，则说明问题并请用户调整；不自行放宽明确的单程时限。用户选定或确认一处后，才展开行程、吃、住、玩；如果用户起初已指定目的地，则跳过候选阶段，直接从已知条件给出带假设的初稿。后续反馈只调整相关行程，保留仍有效的条件。

### 4. 明确偏好持久化的边界

对话中表达的喜好立即可用于当前行程，但只有明确说“记住”“以后都这样”或确认保存时才更新偏好资料；临时安排和模型猜测不能写入。资料采用简短的 Markdown 分类，例如倾向、回避、节奏与限制，不预设这些类别必须填满。改变或撤销偏好时修改相应条目，避免留下互相矛盾的默认值。相比每次反馈自动学习，这种做法减少误记和个人资料在仓库中无意扩散。

### 5. 时效信息按可用工具核实

指令要求针对会影响候选可行性或攻略执行的单程交通时间、开放时间、票价和交通班次使用当前环境可用的查询工具；核实结果带来源或查询依据。没有工具、权限或可靠结果时，在候选或攻略中明确列为待核实，不用伪造的具体数字填补。设计不绑定某个搜索服务，便于在不同执行环境使用。

## Risks / Trade-offs

- [仓库中的偏好文件可能被同步或公开] → 只保存用户明确要求长期保留的非敏感偏好；涉及敏感资料时先确认存放方式，不默认写入。
- [初稿可能因缺少日期、预算而不够精确] → 将这些取舍作为假设或待确认事项，收到反馈后再收紧路线。
- [候选地可能不满足单程时间或预算] → 说明核实依据和不确定性；已知不符的地点不列为符合约束的候选，必要时请求用户调整条件。
- [实时信息来源可能不可用或过期] → 把核实状态写在攻略中，关键时效信息在出发前提示重新确认。

## Migration Plan

这是新增的项目级 Skill，不迁移现有数据或调用方。实施时新增独立目录；如需撤回，仅移除本次新增的 Skill 文件，并保留用户后续实际填写的偏好资料供其自行决定如何处理。

## Open Questions

- 个人喜欢的地点类型、饮食、住宿、节奏和预算倾向可以在后续真实规划中逐项确认；初版不以这些答案作为实施前提。
